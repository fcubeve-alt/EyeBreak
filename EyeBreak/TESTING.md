## 1. 检测机制说明（测试前必读）

`DeviceActivityEvent` 的 threshold **在一个监测区间内只触发一次**，不会重新武装；
`DeviceActivitySchedule` 的区间**最短 15 分钟**。因此无法做「5 分钟滚动窗口反复计数」。

实际实现：在同一个日区间里挂**一排递增阈值事件**（累计用量每 step 分钟一个），
记录每次回调的真实时钟，用**使用密度**判断连续性：

```
密度 = 用量增量 ÷ 真实时钟增量
```

- 目标 30 分钟 → step 5 分钟，里程碑 5/10/15/…
- 判定：**25 分钟用量在 ≤35 分钟真实时间内跑完** → 判为连续 → 触发
- 相邻里程碑之间，真实时钟比用量多出 **5 分钟以上** → 判为充分休息 → 连续链清零

## 3. Kill Test #1：连续使用识别

先把「目标连续用屏」调到 **2–5 分钟**（v0.3 步骤 2），跑通后再改回 30。

| 场景 | 操作 | 预期 |
|---|---|---|
| 1-A | 连续使用达到目标时长 | **应触发** |
| 1-B | 用 20 分钟 → 放下 **5 分钟以上** → 再用 10 分钟 | **不应立即触发**，连续链应清零重新计 |
| 1-C | 用 5 分钟 → 长时间不用 → 再用 5 分钟 | **不应**按累计 10 分钟处理 |
| 1-D | 在多个 App 之间切换但屏幕一直在用 | **仍应**视为连续 |
| 1-E | 锁屏 / 设备闲置 | 应识别为休息并重置 |

> 按比例缩放：目标设 2 分钟时，1-B 的「休息 5 分钟」仍按 `restGapMinutes = 5` 判定，
> 所以短阈值测试时休息也要真的超过 5 分钟才会看到重置。

## 4. Kill Test #2：可关闭的护眼引导

| 场景 | 预期 |
|---|---|
| 2-A | 达到阈值后可靠弹出引导界面 |
| 2-B | 界面有存在感（Shield 遮罩，非普通横幅） |
| 2-C | 动作引导清晰（有视频则播视频，无视频则 4 个动作可选） |
| 2-D | 点「稍后再说」立刻返回原 App，正常继续使用 |
| 2-E | 完成动作后有明确反馈并解除界面 |
| 2-F | 整个流程可重复、稳定 |

## 5. 安全兜底自检

| 项 | 预期 |
|---|---|
| Shield 超时 | 应用后超过 20 分钟未解除 → 自动强制解除 |
| 扩展失效 | 打开主 App 即触发兜底解除；调试区另有「强制解除 Shield」按钮 |
| 跨天 | 第二天里程碑链、Layer 1 缓存、当日计数全部清零 |
| 冷却期 | 关闭后 15 分钟内不再弹 |
| Layer 1 陈旧 | 数据超过 15 分钟未刷新 → 显示「已过期」且不参与触发判断 |

## 7. Go / No-Go

**GO**（v0.3 第五节，两项同时成立）：
- A：能可靠近似实现「连续真实使用约 30 分钟，中途充分休息则重置」
- B：达到阈值后弹出有存在感、可关闭的护眼引导，关闭后不影响正常使用

**NO-GO**：
- 只能拿到累计用量，完全无法区分连续与分散使用
- 弹出界面存在感太弱，与普通提醒器无本质区别
- 关闭路径不顺 / 频繁崩溃
- Family Controls entitlement 无法获得

按 v0.4 第八节，只要 A / B / C 任一层级成立即可继续；
真正的 NO-GO 是三层全废、提醒退化成脱离真实使用的普通闹钟。
